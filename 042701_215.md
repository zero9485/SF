# Self-Skill Learner

A skill for improving other skills (including itself) using repeatable feedback loops.

## Mission

Turn weak or inconsistent skills into reliable, reusable skills by iterating on:
- trigger quality,
- instruction clarity,
- output quality,
- and success rate across realistic prompts.

## Timeout Guard

- Run one focused improvement pass per turn.
- Prefer minimal edits over full rewrites.
- Evaluate with a small representative prompt set only.
- Record only high-signal learning for the next pass.
- Finish within a single concise report.
- When a prior evaluation or critique names a specific failure mode, re-check that same signal after the edit—not only easier proxy checks—before claiming improvement.
- Under tight step or time budgets, ship one minimal end-to-end slice first: smallest edit, run the agreed evaluation or checks, persist the skill artifact the way the environment expects—then iterate; avoid ending on analysis alone.
- Before treating a pass as complete, confirm acceptance: targets named in the request are updated, checks or evals were run, and any required durable hand-off (saved file, published pack, etc.) exists if the setting requires it.

## Common Operating Principles

- Read only the docs/context required to execute correctly before acting.
- Follow the user instruction exactly; avoid paraphrase and unrequested improvements.
- Keep scope surgical: change only what the request names.
- Verify outcomes using available validators, tests, or reviews; do not rely on intuition.
- Keep communication concise and direct.
- Prefer fewer, bundled tool invocations over fragmented calls.
- If a persistent note surface exists, leave a short generalized note for future runs.

## What To Improve

### 1) Triggering Quality
- Make description explicit about when to use the skill.
- Include multiple natural-language trigger cues.
- Avoid vague wording that causes under-triggering.

### 2) Instruction Quality
- Remove duplicated or conflicting rules.
- Prefer clear rationale over rigid, brittle prescriptions.
- Ensure steps are actionable and ordered.

### 3) Output Quality
- Define expected output structure when useful.
- Ensure outputs are useful to the user's likely audience.
- Emphasize factual grounding and explicit uncertainty.

### 4) Reliability
- Stress test with varied prompt styles (short, long, messy, casual).
- Ensure behavior remains stable across similar prompts.
- Reduce reliance on fragile wording hacks.

## Stop Criteria

Stop when one of these is true:
- targets are met for two consecutive iterations,
- improvements become marginal,
- or user approves final version.

## Guardrails

- Do not fabricate evaluation outcomes.
- Do not claim improvements without evidence.
- Do not optimize only for benchmark prompts (avoid overfitting).
- Do not broaden triggers so far that unrelated tasks invoke the skill.
- Do not assert the skill is fixed until the saved or published skill body matches the claim and evidence supports it.
- Do not bundle unrelated refactors, filler sections, or off-scope trigger churn into the same pass as the requested fix.
- Label hypothetical or draft rewrites as such unless they are actually present in the durable artifact the environment will read.
