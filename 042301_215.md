# Self-Skill Learner

A skill for improving other skills (including itself) using repeatable feedback loops.

## Mission

Turn weak or inconsistent skills into reliable, reusable skills by iterating on:
- trigger quality,
- instruction clarity,
- output quality,
- and success rate across realistic prompts.

## Core Loop

Run this loop until stop criteria are met:

1. **Assess**
   - Read the current skill frontmatter and body.
   - Identify likely failure modes (under-triggering, ambiguity, over-constraint, missing guardrails).
   - Define measurable targets for this iteration.

2. **Hypothesize**
   - Propose the smallest high-impact change.
   - Explain why that specific change should improve behavior.

3. **Edit**
   - Update the skill with focused modifications.
   - Keep instructions concise and generalizable.
   - Preserve the skill's name unless the user explicitly asks to rename.

4. **Evaluate**
   - Test with realistic prompts that represent real user intent.
   - Include edge cases and near-miss prompts.
   - Compare outcomes against the prior version.

5. **Learn**
   - Record what improved, what regressed, and what is still uncertain.
   - Keep lessons that generalize; discard one-off noise.

6. **Plan Next Iteration**
   - Choose one next improvement with the best expected payoff.

## What To Improve

### 1) Triggering Quality
- Make description explicit about when to use the skill.
- Include multiple natural-language trigger cues.
- Avoid vague wording that causes under-triggering.

### 2) Instruction Quality
- Remove duplicated or conflicting rules.
- Prefer clear rationale over rigid, brittle prescriptions.
- Ensure steps are actionable and ordered.

### 3) Output Quality
- Define expected output structure when useful.
- Ensure outputs are useful to the user's likely audience.
- Emphasize factual grounding and explicit uncertainty.

### 4) Reliability
- Stress test with varied prompt styles (short, long, messy, casual).
- Ensure behavior remains stable across similar prompts.
- Reduce reliance on fragile wording hacks.

## Evaluation Framework

For each iteration, track:
- **pass_rate**: fraction of prompts meeting expectations.
- **trigger_precision**: how often the skill triggers when it should.
- **trigger_recall**: how often it fails to trigger when needed.
- **quality_notes**: concise qualitative observations.

Use realistic eval prompts:
- 8-12 should-trigger prompts.
- 8-12 should-not-trigger near-miss prompts.
- Prefer tricky boundary cases over obvious ones.

## Iteration Output Template

For every cycle, report:
1. **Hypothesis**
2. **Change Made**
3. **Evidence**
4. **Learning**
5. **Next Step**

## Stop Criteria

Stop when one of these is true:
- targets are met for two consecutive iterations,
- improvements become marginal,
- or user approves final version.

## Guardrails

- Do not fabricate evaluation outcomes.
- Do not claim improvements without evidence.
- Do not optimize only for benchmark prompts (avoid overfitting).
- Do not broaden triggers so far that unrelated tasks invoke the skill.

## Trigger Examples

This skill should trigger for prompts like:
- "Improve this skill so it triggers more reliably."
- "Run an iteration loop to make this skill better."
- "Analyze why this skill underperforms and rewrite it."
- "Tune the description and instructions based on eval results."
