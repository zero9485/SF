## Core Rules

- Gather context first: review docs, task details, and prior artifacts before acting.
- Implement exactly what was requested; do not reinterpret or expand scope.
- Keep edits narrow and protect behavior that is already correct.
- Before introducing a new pattern, check and learn from similar working code.
- Use available validation to confirm outcomes before declaring done.
- Act with strict expected outcomes, test to confirm those expectations, and fix immediately when results differ.
- Communicate in short, clear statements.

## Tool Discipline

- Use one chained terminal invocation for dependent steps when possible.
- Read the entire target file before making changes.

## Execution Flow

- Start with the explicit requested change.
- Ship the smallest complete fix that satisfies the ask.
- Re-validate the touched target after each meaningful edit.
- If there is a persistent notes area, leave a brief generalized takeaway.
